# Changelog (Beta)

All notable changes to the beta channel are documented here.
Format follows https://keepachangelog.com/en/1.1.0/

## [Unreleased]

## [1.9.10b] - 2026-08-03

### Fixed
- A damaged file no longer skips to the next part of the book. The recovery that steps past a corrupted section wasn't checking whether its skip landed beyond the end of the file — when it did, playback rolled straight into the next part instead. With every part of a book damaged this cascaded through the whole book and then, on reaching the end, marked it finished and auto-advanced into the next book of the series.
- A file whose damage genuinely can't be skipped now stops on that file instead of playing on, so you're left where the problem actually is.
- Recovery no longer trusts a damaged file's reported length. A corrupted header often makes a multi-hour file report a few seconds, which made every skip look like it ran past the end; the length is now cross-checked against the scanned duration and falls back to the byte-level skip when it looks wrong.

## [1.9.9b] - 2026-08-01

### Fixed
- Audiobooks whose **first** seconds are corrupted now actually play. The recovery that skips past a damaged file start has been silently doing nothing since it was added — the playback service was discarding the skip and handing the decoder the same broken opening on every retry, so the book always ended on "Couldn't skip past the damaged section". Damage partway *through* a file was unaffected and always recovered correctly.

## [1.9.8b] - 2026-08-01

### Fixed

- Chapters past the 255th in a single audio file are no longer silently dropped.
- Listening history recorded while playing a series member book now records the correct chapter instead of a whole-series index.
- The widget's chapter title and chapter progress fields now track the actual chapter instead of standing in for the whole file.

### Added

### Changed

## [1.9.7b] - 2026-07-20

### Changed
- The widget editor is redesigned as a photo-editor-style workspace: persistent docked panels for Elements/Layers/Options (no more sheets covering the canvas) with Copy/Delete/Collapse in the same dock, and a pannable/zoomable canvas that isn't limited to the widget's own shape — zoom out to see it floating in the workspace, zoom in past its edges, pan anywhere.
- The widget itself is now always a plain rectangle. The Background element is a normal movable/resizable/rotatable layer like any other — including rectangle, pill, and round shape options, cover/image/color/gradient fill, and dim/blur/opacity — it just starts full-bleed and at the bottom of the stack by default.
- The custom color picker now has a visual hue + saturation/value picker alongside the hex/alpha fields, and any custom color you set is saved and offered as a swatch for every other color picker in the editor.
- The widget designs list's ⋮ menu now shows an icon next to Rename, matching Edit/Duplicate/Delete.
- The Material You theme now keeps the last-played book's cover as the app's accent color after you close the book, instead of reverting — it only changes when a different book is opened.
- The series info screen now opens/closes with the same smooth cover-morph animation as Book Info (it was jumping to/from nothing before, since it tore down the library grid mid-animation).

### Added
- Progress bar elements can now be a line, a circle, a square, or a rounded-corner square, with a settable stroke width — progress sweeps around the outline for the non-line shapes.

### Fixed
- Removed the last "headphones" placeholder icon (used only as a cover fallback in the widget) in favor of the app's own icon.
- The mini player no longer shows on the Widget designs screen (it already didn't on Settings/the editor itself).
- Some Settings buttons could squeeze down to one letter per line on narrow screens — the affected rows now scroll horizontally instead.

### Changed

### Added

## [1.9.2b] - 2026-07-19

### Fixed
- Widget "problem loading widget" — the real cause: the widget layout used a view type the home-screen widget framework doesn't support for its tap grid, so the whole widget failed to inflate. Switched to a supported view type (and added a safety net that shrinks the render if the system still rejects it as too large).
- Widget editor: dragging an element now moves it the full distance you drag. The move gesture was fighting itself because the element being dragged was also the touch surface; the gesture now lives on a fixed layer so movement tracks your finger exactly.

## [1.9.1b] - 2026-07-19

### Fixed
- Widgets that showed "problem loading widget" now load: the render was building a far-too-large RemoteViews (an oversized bitmap plus a tap target on every one of 256 grid cells), which overran the system's transaction limit. The tap grid is lighter now and only interactive elements get tap targets.
- Widget editor: dragging an element now moves it instead of resizing it. Move/resize/rotate were fighting over the same touch area on smaller elements — the resize and rotate handles now sit outside the element, so the whole body reliably drags to move.
- Refreshed several widget icons (speed, boost, skip-chapter, bookmark) to a cleaner, more consistent look that matches the rest of the app.

## [1.9.0b] - 2026-07-19

### Added

### Fixed

- The old retired "join books into a group" feature's leftover code and database tables (superseded by Series long ago; it had no working entry point)
